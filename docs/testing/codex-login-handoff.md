# Codex 登录、退出与换号：交给 Leo 的核对清单（Issue #13）

本文件是 Issue #13 交付给 Leo 的手测核对项，覆盖登录、身份、存储引用隔离、退出与撤销。
本票的 Agent 部分只用隔离替身与本地假回调验收，**不执行真实 OAuth／浏览器登录、不读取日常凭据、不调用真实模型**。
真实登录、真实账号与真实存储保护由 Leo 在 [#25 Codex 真实验收与受控启用](https://github.com/LC-86/JevModelRouter/issues/25) 中执行并回填；
本清单只列出 #13 需要 Leo 额外确认的项，不重复 #25 的完整 HAND_RUN 包。

## 2. Agent 已给出的隔离证据

Agent 侧证据来自假 Codex app-server 替身与隔离桌面验收，**只证明受控行为，不证明真实授权成立**：

- 登录成功／失败／取消三种终态，以及取消后到达的迟到结果被整体丢弃。
- 退出与换号使连接世代递增，旧身份、额度、目录与能力缓存被清除，服务商、模型与路由配置保留。
- 换号失败不自动恢复旧账号。
- 辅助进程使用专用授权目录（`<应用数据>/.autojev/helpers/codex/<服务商>`），日志与错误中不出现令牌或授权码原文。
- 退出会删除该专用授权目录：替身写入的虚构凭据文件在注销后消失，而用户真实的 `~/.codex` 存在性与 inode 不变、其中不出现本应用的凭据文件。
- Grok 订阅行不借用 Codex 辅助进程：状态显示为不可用，点登录得到明确的「未实现」错误且连接状态、世代与身份均不变。
- 桌面进程正常退出只回收本应用自己拉起的辅助进程，无关进程不受影响。
- 挂起登录期间桌面退出后重启：late 运行带着挂起登录退出（`state=authorization_pending`、身份为空），下一次桌面启动读回 `state=not_connected`、行文本 `login=idle`，且可立即重新登录；Rust 单测另行覆盖启动回收孤立的 `authorization_pending` 与取消的幂等 settle。
- 真实生成入口在已连接状态下仍被拒绝，替身未收到任何生成请求。

两处 Agent 侧的验证边界，如实标注：

- 授权链接的放行只做**静态断言**（`src-tauri/capabilities/default.json` 已放行 `auth.openai.com` 与 `chatgpt.com`）；真实打开浏览器未执行。
- 真实 `~/.codex` 的 mtime 在本机被用户自己的 Codex 客户端持续写入，因此改用「存在性 + inode + 其中不得出现本应用凭据文件」这些可归因断言；严格 mtime 比较只在安静环境执行。

## 3. 交给 Leo 的真实核对项

逐项填“通过／失败／未测”并附脱敏证据位置（勿贴令牌原文）。

### 3.1 登录与身份

- [ ] 从应用界面发起登录，浏览器打开的是官方授权页，应用自身注册身份而非其它客户端身份。
- [ ] 应用只放行 `auth.openai.com` 与 `chatgpt.com` 两个主机的授权链接；若官方授权页落在其它主机，界面会把完整链接显示在订阅行里，请手动复制打开并在回报中记下主机名。真实打开浏览器未在 Agent 侧执行。
- [ ] 授权完成后界面显示**已核实身份**；身份来自令牌校验结果，不是从邮箱或 API Key 推断。
- [ ] 登录完成前界面保持等待授权，不显示为已连接、不放行生成。
- [ ] 界面显示的账号与官方客户端中看到的账号一致；不一致时停止并回报。

### 3.2 存储与引用隔离

- [ ] 应用使用的授权目录位于本应用自己的受保护位置，**没有读取或改写日常 Codex／DSH 的登录文件**。
- [ ] 对比操作前后的日常客户端凭据文件：内容与修改时间均未变化。
- [ ] 应用界面、日志与错误信息中不出现令牌、授权码或刷新令牌原文。
- [ ] 应用配置文件中只保留非秘密的身份摘要，不含秘密。

### 3.3 退出、换号与撤销

- [ ] 退出后新请求立即被拒绝；界面同时展示**本地清除结果**与**远端撤销结果**，两者不互相冒充。
- [ ] 远端撤销不确定或失败时，界面如实显示，不标为“远端授权已验证”。
- [ ] 退出后服务商、模型与路由配置保留，模型显示为不可用而非被删除。
- [ ] 换号成功后旧账号不再可用；换号失败时不自动恢复旧账号，需重新发起。
- [ ] 退出或换号后，在途请求与异步刷新结果不复活旧连接。
- [ ] 关闭应用后，应用拉起的辅助进程已退出；无关的其它进程不受影响。

### 3.4 禁止额外消费

- [ ] 未取得 Leo 明确允许前，不使用真实生成入口，不试探 credits 或额外用量。
- [ ] 真实验收中的调用次数、模型与输入由 Leo 运行前填写确认，未知费用记为未知，不填 0。

## 4. 失败停条件

出现以下任一情况时停止并回报，不自动重试、不扩大调用、不切换来源：

- 身份或账号与预期不符；
- 无法确认仅消耗订阅内额度，或出现异常 credits 状态；
- 登录／退出／撤销结果与界面显示不一致；
- 发现应用读取或改写了日常客户端凭据；
- 需要超出 Leo 已确认的调用次数或模型范围。
