# Grok 人工验收入口（Issue #26）

**本提交状态：安全代码验收可执行；真实 Grok HAND_RUN 阻塞。** 当前生产路径没有经过核实的 CLI 机器登录/身份、订阅模型资格、额度和整次调用 Extra Usage 禁止条件接口。界面有一个默认关闭、进程内存态、最多 15 次请求的 Grok 生成许可；但只有经过核实的登录合同才可启用，当前登录支持为 false。许可的范围是当前连接下所有已核实资格模型和协议，不能锁定到 HAND_RUN 中计划的单个模型/协议；因此确认时明确告知此账号级范围。即使将来许可被打开，生产 Grok 适配器仍在此构建中 fail-closed，直到另行实现并审查。此开关不是生成或真实账户操作授权。

## 本提交可执行的安全验收

在该提交的仓库根目录运行：

```sh
pnpm test:grok-contract
```

通过标准：

- 未注入协议的生产 Grok 登录在启动 helper 或创建应用 home 之前拒绝；返回 `grok_auth_unverified`，`login_supported=false`。
- 生产状态、目录与订阅额度读取保持 `Unknown`，并且不启动 CLI。身份、目录资格、额度来源/时间与 Extra Usage 整次调用限制均不能由 session 用量推断。
- 未连接状态中留下的旧身份不显示为当前已核实身份；未知 Extra Usage 权限阻止派发。
- Grok 生成开关默认关闭、仅绑定当前连接世代、不跨重启保留；未核实的登录接口下 UI 与 IPC 都拒绝启用。
- 生成许可为当前账号下所有已核实资格模型/协议的账号级同意，HAND_RUN 仍要求操作者逐项确认并仅使用具体计划范围。
- 即使 fake 测试显式启用 Grok 许可，未知额度或无法证明整次调用不使用 Extra Usage 仍拒绝派发；请求预算不能被调高。
- 本地显式注入的 fake helper 可以验证内部事件解析；fake 协议不能改写生产默认值。

该命令只运行离线 Rust 单测和前端纯函数测试，不调用 `grok`，不启动 ACP，不开浏览器，不读 CLI 设置、session 或凭据，不发送模型请求，也不消费额度。它验证 fail-closed 回归，不证明上游服务、账户权益或费用行为。

结果请填入 [结果模板](grok-hand-run-result-template.md)，将真实登录、读取与生成项记为“阻塞”或“未测”，不要填成通过或用量为 0。

## 当前版本可见行为

| 检查 | 本提交预期 | 允许的操作 |
| --- | --- | --- |
| Grok 登录按钮 | 不可开始登录；说明机器身份接口未核实 | 只观察状态，不点击登录、退出或换号 |
| 身份、目录与资格 | `Unknown` / 未核实 | 只运行上面的 fake 契约测试 |
| 订阅额度与整次调用 Extra Usage 限制 | `Unknown` / 未核实 | 不运行任何用量读取或生成 |
| Grok 生成许可 | 默认关闭；当前登录接口未核实，UI 和 IPC 拒绝启用 | 只观察；不要尝试绕过禁用状态 |
| Grok 生产生成 | 后端生产入口拒绝，即使许可被 arm 也不进入生产 ACP | 不发送 Chat Completions、Responses 或 Messages 请求 |

`grok models` 是公开 CLI 命令；命令存在不等于它有已核实的机器输出格式或账号资格语义。`grok login` / `grok logout` 也存在，但其机器事件与 AutoJev 身份读取合同未被核实。`grok account` 不存在；`models --help` 没有列出 `--json`；`usage` 要求本地 session ID，描述的是 session token/cost，不能代替订阅池或 Extra Usage 权限。ACP `session/prompt` 会生成内容，不是只读账户接口。

## 将来解阻后的人工验收矩阵

以下真实账号与生成步骤**当前全部阻塞，不能在本提交上运行**。只有在上游提供版本化接口合同、生产适配器已实现并再次通过独立审查后，才将“阻塞”变为可执行步骤。真实 OAuth、账户、额度和模型请求由用户本人操作；Agent 不运行这些步骤。

### 1. 隔离和版本

1. 记录完整 AutoJev commit、构建类型、系统、时间及时区。
2. 用专用可丢弃 OS 用户或等效隔离环境启动验收构建；记录应用自有 `HOME` / `GROK_HOME` 与 helper 精确路径、版本、SHA-256。确认真实日常 `~/.grok` 不会被读写。
3. 操作者自行选择测试账号别名及有上游明确支持的 CLI 版本。只记录非秘密别名；不记录完整邮箱、密码、token、授权码或配置内容。版本、路径或隔离不符时停止。
4. 先确认 UI 许可开关默认关闭。合同与手测前置证据齐备、操作者接受有限预算后才可启用；许可只绑定当前连接世代、重启后复位，不能改变 Unknown 或准入结果。在执行任何生成前，先填写结果模板中的协议/模型、允许输入与工具、最大 dispatch/helper turn/工具轮次/输出 token 数和可能费用。每个被准入的 API dispatch 消耗一个总预算槽，即使之后失败或取消；成功进入 helper 时，每个 dispatch 发出一个 ACP `session/prompt`。客户端工具结果续传是新的 API dispatch 和 helper turn，另占一个槽。分别记录 dispatch 数与实际 `session/prompt` 数；两者不得超过同一个固定总上限。任何费用边界或订阅内限制为 Unknown 时，预算保持 0 且不得继续。

### 2. 登录、身份、目录、退出与换号

在隔离 home 中登录所选账号；验收界面中的连接世代、脱敏账号别名、登录终态及 helper 版本。核对目录来源/时间、逐模型资格、订阅额度来源/时间，以及 Extra Usage 的整次调用权限。未知或缺失字段必须显示 `Unknown` 并拒绝生成。验证登出只报告实际观察到的本地清理和远端撤销结果；再切换到已批准的第二个测试账号，确认旧身份、目录、额度、能力与工具轮次不跨世代保留。不要把“本地 session usage”当作订阅额度。

### 3. 生成矩阵

只有前置证据全部通过、用户填妥有限预算并显式启用本次验收后，才对同一个已验证账号、模型与 build 分别执行 Chat Completions、Responses、Messages。输入仅用虚构短文本 `Reply exactly: HAND_RUN_OK`。工具用本地假工具 `fixture_lookup({"item":"fixture-1"})`，结果固定为 `{"value":"fixture-value"}`，不得接外部网络或真实数据。

| 每个协议 | 步骤 | 可观察通过标准 |
| --- | --- | --- |
| 文本 | 发送一次虚构短文本 | 正常终态；没有意外工具调用；计数与费用观察符合预算 |
| 流式 | 发送一次同样的短文本并收集流 | 顺序完整、终态唯一；没有重复派发或跨账号事件 |
| 取消 | 开始一次受预算覆盖的生成并立即取消 | AutoJev 显示取消终态；不重试；helper/request 在有限时间内停止 |
| 客户端工具往返 | 仅允许 `fixture_lookup`，最多一轮工具调用及一次结果续传 | call ID、参数、结果与协议关联一致；无额外工具、重复调用或自动重试 |

上表每协议最多 5 次 dispatch（文本 1、流式 1、取消 1、工具往返最多 2），三协议合计最多 15 次；helper turn 由总 dispatch 上限一并约束，客户端工具续传另计一次。该值是**待操作者逐项明确接受的测试上限，不是本提交授予的费用额度**。用户确认预算之前不执行；实际模型/费用成本仍必须由上游证据或账户界面确认。拒绝限制上限上调、自动重试、换模型或换账号来“补测”。

### 4. 立即停止条件

任何请求失败或出现 `failed` 终态，都必须立即停止全部剩余步骤并回报；不因错误提示重试而继续。请求或取消的终态不明也立即停止。遇到任一条件即停止剩余步骤，不再登录、刷新、重试、切账号或切 API：build/helper/账号身份不匹配；隔离 home 不确定或触及日常 home；身份、模型资格、协议能力、额度来源/时间或 Extra Usage 整次调用权限为 Unknown；任一请求的实际响应模型、身份或协议与事前计划不符或为 `Unknown`；观察到额度/权限与事前证据不符；调用或工具轮次将超过上限；未知工具、协议语义不匹配、取消不能确认、出现未预期派发或身份变化。保留脱敏错误和计数证据并立即回报，结论写“失败”或“阻塞”，费用未知写 `Unknown`。
